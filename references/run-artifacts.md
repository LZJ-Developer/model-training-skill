# 任务契约与运行产物

产物的作用是让审阅者重建运行条件、复查结果，并知道结论的边界。长期训练、正式比较和恢复任务需要完整记录；短时排障可引用已有任务卡，只补本次改动、实际命令、结果与未决项。已有信息可直接复用并指出来源，不要求每次重新问答或填完所有表格。

## 1. 任务卡：先固定问题

在 `task.md` 或项目已有配置/文档中维护一份任务契约；各次运行引用其版本或哈希。缺失且会改变决策的字段才需向维护者确认。

| 字段 | 需写清的内容 |
|---|---|
| 预测对象与部署输入 | 输入、输出、目标表示/单位、缺失与掩码语义；部署时可取得哪些数据和 evidence |
| 泛化与切分 | 未见背景、未见扰动或两者同时未见；训练/验证/最终测试的实体键、排除规则与切分清单 |
| 独立单位 | 监督行、细胞、供体、样本、文库分别是什么；推断和不确定性估计以哪种单位进行 |
| 评测与选择 | 指标定义、方向、分母、聚合权重、基线、成功判据；checkpoint/超参仅用允许的验证分区选择 |
| 资源与范围 | 可用硬件、数据许可、预算/时间上限、扩算力停止条件；尚未验证的假设 |

最终测试响应保持封存，按预定协议做最终评估；只要测试结果指导了方案修改，该分区就不能继续支持独立最终检验的主张。扰动任务的单轴留出与双轴同时留出分别记录，不能将前者的结果当成后者。

## 2. 最小可追踪目录

```text
outputs/<date>_<slug>_<seed>_<run-id>/
  config.yaml        实际解析后的配置
  provenance.json    代码、数据、切分、模型与评测器的身份
  run.md             紧凑结果与解释，链接到原始记录
  metrics.tsv        可机读的原始指标与分量
  checks/            关键边界的检查、对照与故障注入证据（按任务选择）
  samples/           适量脱敏示例或受控本地引用（按需）
  ckpt/              checkpoint 与恢复状态（按需）
```

新运行使用唯一 run ID；同 seed 复跑也新建目录，不覆盖旧产物。仅明确执行恢复时写回原 run，并记录恢复事件。无需改造已有目录结构，只要信息可定位。`config.yaml` 必须反映默认值、命令行覆盖和环境解析后的**实际生效值**，并过滤凭证。`provenance.json` 至少能定位：

- 代码 commit 与未提交差异的快照/哈希、实际 argv、任务卡版本；
- 数据版本/内容哈希、预处理产物、实体别名映射与 split manifest；
- 模型结构和权重版本、tokenizer/特征/基因顺序、evidence 构建规则及掩码；
- 评测器代码与版本、配置/渲染/抽样设置、seed、库与硬件环境。

使用外部特征或派生缓存时，关联各通道的 required/optional 状态、源版本/摘要的可信程度、row-ID 与消费索引身份、生成/变换配置、探针和 policy 版本、审计范围/采样设置、内容报告及真实 loader 覆盖。仅保存“preflight pass”不够；旧报告与当前身份不匹配则失效。可选通道的显式降级及检查未完成也写入配置和 run 状态，详见 [payload-integrity.md](payload-integrity.md)。

跨数据、更新和评测的静默检查还需关联所支持的主张/前提、独立参照、实际执行阶段、判据、pass/fail/unknown/skipped 与失败动作，按 [silent-failures.md](silent-failures.md) 复用已有记录。注明是文档、合成检查、真实路径接入还是科学结论重验，不能用同一个“已验证”代替不同完成状态。

大型受限数据可记录受控位置和分块清单哈希，无需复制入输出目录或上传。记录访问方式与缺失来源；不应把一个不能访问的路径当成已公开可复现的证据。

## 3. 自动事实与解释分开

训练入口或现有日志系统自动保存配置、原始指标、阶段/step、耗时、资源和错误。`run.md` 的简表可由脚本生成；科学解释、机制与 caveat 由维护者或 agent 根据证据补充，并链接具体产物/记录。脚本生成一句解释不等于验证了它。

```text
run:       <run_id>  seed: <s>  code: <sha>  config: <hash>
status:    planned | running | completed | failed | interrupted
question:  <本次比较回答什么问题>
changes:   <相对哪个参照版本改了什么>
result:    <分量指标、配对差值与不确定性；尚无结果则写未完成>
sources:   <原始指标、切分、配置、checkpoint 的可定位引用>
caveat:    <尚不能说明什么、哪些检查尚未完成>
```

结果必须区分计划、已启动、已完成和失败；尝试过一种实现不等于排除了整个方向。中断/失败也保存实际执行到的位置和原始错误。

样例应覆盖必要的原始语义与模型消费表示，包括形状、单位、掩码和特殊标记。敏感患者信息、原始组学数据或受限文本不默认写入日志、发给外部模型或上传；使用安全本地 ID、受控引用或明确标注的脱敏示例。保留有诊断价值的失败样例，控制采样数量和日志体积；大张量、长输出可放独立受控产物并在 `run.md` 链接，避免巨型报告。

## 4. 比较方式决定能作出的归因

- **版本选型**：可同时修改多个组件，展示实际配置 diff；结论是组合版本相对参照的表现，不能拆成每项的独立贡献。
- **单项机制**：用适当的消融、匹配条件或因子实验隔离变化，并考虑交互。分别对应不同指标并不证明两项改动彼此独立；固定其余组件后测得的是该上下文中的条件效果。
- **探索排障**：可快速试多个候选，但保留改动记录；形成机制主张前补必要对照。

两个实验臂应使用相同的允许数据、切分与评测器。输入信息不同的版本可比较实际效用，但应明确差异；要归因架构效果，需另做信息匹配的比较。指标表保留基线、各分量、方向、分母、配对单位和来源；不只报告复合均值或挑选单个种子的峰值。不确定性按任务卡的独立单位估计，资源有限时说明未估计到的方差。

## 5. 复杂探索时的辅助表

多轮研究或长期排障可维护 `MENTAL_MODEL.md`，包含 `Current model`（当前解释、预测与不确定性）和 `Dated clues`（带日期及来源的未解观察）。下一轮相关实验前读它；保留矛盾，不回写原始观察来迁就解释。一次短跑无需另建研究档案。

按决策需要选择以下表格，不机械要求每次全填：

| 表 | 内容 | 何时有用 |
|---|---|---|
| 选项表 | 改动、预期影响指标、可区分结果、资源成本 | 多条路线需排序时 |
| 预测表 | 什么观测会改变解释、异常表现、所需探针 | 机制检验或长训练前 |
| 尺度表 | 简单基线、合适的零对照、可估上限与判据 | 设定阈值或解释新指标时 |

对照按待排除的解释选用，不要求所有任务都有同一组对照。探索性运行可写要观察的行为，无需编造精确效应量；上限或噪声未测就写“未测”，阈值无依据就明确标注。oracle 仅用于隔离诊断，不能混入可部署模型的性能结果。

## 6. 恢复与 warm-start

**精确续训**需要与框架支持相匹配地保存模型、optimizer、scheduler、精度缩放器（如使用）、RNG、sampler/数据游标，以及梯度累积所处位置和未提交梯度（或只在完整更新边界保存）。还需记录数据/代码/环境及分布式设置。仅有模型权重不能宣称精确恢复；边界不清时从可证明的一致状态恢复，说明重新执行或跳过了哪些数据。

**Warm-start**只复用部分或全部权重，优化器、调度或数据路径可重新开始；应建立新的 run 身份，记录源 checkpoint、载入键/形状差异和重新初始化项。跨环境续跑若只能达到数值容差内的一致，应记录容差与限制，而非承诺逐位相同。

## 7. 报告口径

结论先说明变化及其适用范围，再给分母、对照、来源与限制。观察、推测和决策分开；“计划检查”“已执行”和“证据支持”不得混写。局部失败或证据缺失时写“不确定/待核验”，不写“已排除”。私有或脱敏案例须标注证据可访问性，不能由相对量或上游链接推导出未经提供的复现实验。
