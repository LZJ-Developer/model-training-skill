# HTCA 与 BBOC：两个判断框架

这两个框架用来回答**训练之前**的问题：这次改动落在哪一轴、它能不能起作用、值不值得为它花算力。它们不替代 `SKILL.md` 里的四道检查——那四道是「训了能不能信」。

---

## 1. HTCA：四轴

| 轴 | 问的问题 | 典型改动 | 不算这一轴的声称 |
|---|---|---|---|
| **H 可表达关系** | 允许哪些输入影响哪些输出 | 新增跨基因/跨样本的依赖边；改变条件化的方式 | 只换了 attention 的接法、但依赖集合没变 |
| **T 学习路径** | 训练是否真的奖励部署时需要的行为 | 改损失、改样本构造、改训练题的粒度 | 只加正则/零初始化来「稳住训练」 |
| **C 计算实现** | 用多少计算、怎么分块、怎么共享、压缩到多少维 | 共享记忆、分块解码、容量消融、低秩压缩 | 把「省显存」说成「更强的表达力」 |
| **A 信息获取** | 模型能否自己决定去获取什么信息 | 推理时自主检索、主动选择实验 | **预先准备好外部信息并喂进模型——这只是信息利用，不是主动性** |

**用法**：任何一次改动，先说出它落在哪一轴，再说出它改变了什么可测量的东西。说不出来，就是没改动。

一次四轴自查的实例（本项目的实际记录）：

| 轴 | 当时判断的瓶颈 | 对应行动 |
|---|---|---|
| H | 逐基因证据隔离；已有补偿只是固定线性映射 | 测试输入相关的跨基因证据交互 |
| T | 普通训练没有真的训练「借助其他实验预测新背景」 | 使用模拟部署条件的实验级训练任务 |
| C | 全基因交互昂贵，但固定小秩也可能压缩过度 | 共享记忆、分块解码、容量消融 |
| A | 供体证据丰富，但独立背景有限 | 优先增加有交叉靶标覆盖的背景；检索 ≠ 主动性 |

**常见误标**：

- 把 C 的改动（换接法、换分块）说成 H 的创新 —— 除非依赖集合真的变了。
- 把「接入了一个外部数据库」说成 A —— 那是信息利用。A 要求模型自己决定取什么。
- 把 T 的改动说成 H —— 换损失不改变模型能表达什么，只改变它被推向哪里。

## 2. BBOC：三个问题

BBOC 常被读成「堆算力」，原意不是。它在这个领域最有操作性的部分，是把架构改动拆成三个可检验的问题：

### 2.1 信息进得来吗

**测法**：对可疑的输入 `x`，检查 `∂ŷ/∂x`。

若该偏导**恒为零**，说明计算图里根本没有这条边。此时**增加参数、延长训练、换优化器都不会有任何效果**——网络可以重组已有路径，但不能凭空创造不存在的边。

本项目实测过：对 PIE，跨基因 evidence 的偏导 `∂Δ̂_g/∂e_h`（`h ≠ g`）在全部 18 组（evidence block × 预测头）组合上都是精确的 `0.000e+00`。这不是「学得不好」，是**函数类里没有这一项**。所以第一优先是接通路径，不是加容量。

### 2.2 能在内部流动吗

有边不等于有带宽。

- 固定小秩（如 `D + UVᵀ`）把所有扰动压进同一组响应方向；
- 少量 latent token 会把集合内成员之间的信息压掉；
- 分块解码可能让不同块看不到同一份上下文。

**测法**：改动一个输入位置，看多远之外的输出会移动。移动幅度和距离就是带宽。容量消融（把新增维度从 r=8 扫到 r=32/128）告诉你压缩损失了多少。

### 2.3 训练是否奖励真正需要的行为

前两问过了，第三问仍可能失败：路径通了，但训练题不是部署题的模拟。

**测法**：写出部署时模型看到什么、被要求输出什么；再写出训练时看到什么、被要求输出什么。两者不一致的地方，就是模型会走捷径的地方。

本项目的实例：部署时是「源背景 → 目标背景」，训练时如果按行独立打乱，就没有任何一个前向里包含「同一目标背景的多个扰动」，模型也就学不会「这个响应能否与其他扰动区分开」。所以样本构造要按目标背景分组。

## 3. 原文的实际内容与边界

这一节写在这里，是因为对外引用 BBOC 时，它的地位必须说准。

**来源**：2017 年 Amodei 在 OpenAI 的内部备忘，25+ 页；**从未由作者或 OpenAI 发表**。公开的只有前 3 节（约 10 页），由 Kevin Roose 于 2026-10-06 在 Substack 发布。没有同行评议、没有 DOI、没有完整公开文本。

**原文的主张**：七个因素 —— 算力、参数量、经验数量、经验分布、归一化与条件化、对称性与形状、训练目标。原文的说法是：前六个对了，第七个（训练目标）如果是可学的，就会学到。比喻：雪花不是一块块拼的，是给出物理定律（训练目标）+ 原材料（算力）让它自己成形。

**原文自己的限定**（引用时必须带上）：

> "this is not a precise hypothesis or one I'm super confident in" —— 它是对高层直觉的提炼，不是已证明的定律。

> "none of this implies that scaling up today's exact algorithms will lead to AGI"

**已知的反面证据**：

| 结果 | 内容 | 对 BBOC 的含义 |
|---|---|---|
| Chinchilla（2022） | 参数量与训练 token 应等比扩展；当时的大模型严重训练不足 | 「加算力」不是一个旋钮，参数/数据的分配改变结果 |
| 数据受限扩展（2023） | 固定语料下，重复约 4 轮内几乎无损，之后**增加算力的价值衰减到零** | 语料固定时，算力不是万能杠杆 |
| TinyStories（2023） | 千万参数以下的模型在窄分布上也能生成连贯文本 | 窄任务不需要大模型；「Blob」的下限由分布覆盖决定 |
| 涌现能力再分析（2023） | 所谓涌现随度量方式变化而消失 | 「规模带来的阈值」部分是度量artifact |
| 硬件彩票（2020） | 哪种算法「赢」受可用硬件影响 | 算法优劣不是纯客观量 |

**对训练的实际含义**（这几条比「堆算力」有用得多）：

1. **先让正确的经验进入计算图，再决定为它增加多少计算。** 路径没通时，算力全是浪费。
2. **比步数更重要的是 token（或样本）与参数的比值**，以及训练分布覆盖了什么。1,200 步不是算力量，`步数 × batch × 序列长度 / 参数量` 才是。
3. **分布覆盖是可以直接改的旋钮。** 同一背景加细胞数只降噪声；增加独立背景才增加「不同背景下同一扰动如何变化」的经验。
4. **架构的价值上限是「不挡路」。** 在数据受限时，算法上的聪明通常无法补偿缺失的经验。

## 4. 误用清单

- 把 BBOC 当成「加算力就能解决」——原文明确否认。
- 在一个 `∂ŷ/∂x = 0` 的系统上加参数，然后归因为「模型不够大」。
- 声称 A 轴创新，实际只是预先准备了检索结果。
- 用 H 轴的语言描述一个纯 C 轴的实现选择（例如「更强的跨基因建模」实为换了一种 attention 分块）。
- 拿一个未公开、未同行评议的内部备忘当作实证依据——可以当作研究直觉，不能当作定律引用。
