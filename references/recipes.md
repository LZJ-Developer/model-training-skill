# 超参与预算

两份参照：**任务内已验证过的值**（抄代码，不抄文档）和**通用默认值**。冲突时优先任务内的值，但必须把偏离写进配置。

---

## 1. 优化器与调度

| 项 | 任务内已验证 | 通用默认 | 取舍规则 |
|---|---|---|---|
| 优化器 | AdamW | AdamW | 一致 |
| 峰值 lr | **1e-4** | 3e-4 | 主干冻结、只训适配器时先扫 3e-5 / 1e-4 / 3e-4 三个点，别预设 |
| weight decay | **0.01** | 0.1 | 小样本任务用较小 wd，减少对有限数据的额外压制 |
| β2 | 默认 0.999 | 0.95 | bf16 下 0.95 更稳；纯适配器训练差异不显著 |
| eps | 默认 1e-8 | 1e-10 | 只在 bf16 下需要 1e-10 |
| 梯度裁剪 | **10** | 1.0 | 抄任务内已验证值。裁剪阈值是任务量级属性，不是通用常数 |
| 调度 | warmup 5% → 常数 → 尾部短 cosine | cosine 或 WSD | 见第 2 节 |
| 精度 | bf16 | bf16 | 一致。fp16 只在老卡上用且必须配 GradScaler |
| batch | 16 × 累积 4 = 64 | 显存允许的最大值 | batch 是速度旋钮不是质量旋钮；改 batch 必须重调 lr |

**抄代码不抄文档**：文档常落后于代码。上表的任务内值来自训练入口与实验配置的实际取值。

---

## 2. 学习率调度

```
warmup（5%）→ 常数平台 → 尾部 cosine 收尾（短）
```

- **warmup 1–5%**。适配器训练不需要更长。
- **尾部衰减不是普适改进，必须测。** 通用经验说衰减决定最终质量；但在短训练（千步级）且任务指标对预测锐度敏感时，衰减可能明显变差。

  本仓库实测：1,200 步上加入 warmdown，综合分 **−0.039**，损失集中在需要锐度的分量（签准、检出集）——衰减磨平了 DE 判定。同时读数层（逐基因误差）反而更好。这是「读数层与评分层排序相反」的又一个实例。

  结论：**不预设，作为一项超参对比测一次**，并用评分层的口径判定。

## 3. 参数量预算

按**监督行数**（不是标量数、不是细胞数）选策略：

| 监督行数 | 策略 |
|---|---|
| < 10K | 线性探针 / 闭式解为主，不要训深模型 |
| 10K–100K | 冻结主干 + 小适配器 |
| > 100K | 才考虑全量微调 |

**参数/样本比**是更直接的刻度。经验上限约 30:1。

本仓库的实例：86,087 行；完整 Transformer 块形式的新增分支 10.15M 参数 = **118:1**（超上限 4 倍）；去掉 FFN 后约 2.4M = **28:1**（刚好在上限）。这是选择小版本的**唯一**理由——不是「小模型更好」，是「这个比例下大版本是高风险动作」。

**诚实标注**：冻结优于全量在这类任务上**没有一手强证据**。有报告两者可比，也有报告预训练权重与随机初始化无显著差异。冻结的正当理由是风险控制。

---

## 4. 必须记录的偏离

配置里维护一张表，每行一个偏离：

```
项 | 任务内值 | 通用默认 | 我们的值 | 理由 | 依据（源码/实测/无）
```

没有「依据」列，偏离会在三个月后变成无法解释的魔法数。特别是：

- 裁剪阈值
- batch 与 lr 的耦合
- 任何手工的损失权重
- 任何在「别人的默认值」上做的改动

---

## 5. 损失权重

通用先验：权重全部为 1，只做类别频率反比加权，并设上限（常见 10 和 5）防止稀有类把梯度吃掉。

这类任务上**很少有人系统扫过损失权重**，所以：

- 它便宜（一次 sweep 12 GPU·h 级）；
- 它通常是可发表的小贡献；
- 但它是**最后**才动的旋钮——在 lr、数据、容量都稳定之后再扫，否则你扫的是噪声。

---

## 6. 预算的估算方式

- 单次训练成本 ≈ 参照任务的成本 × (新增可训练参数 / 参照任务参数量)，再乘一个 2–3 的安全系数（数据管线、评估、重跑）。
- 实验阶梯按「每个实验 × 3 种子」估，不要按单次估。种子噪声在 0.03 量级时，单次结果无法判决。
- 渲染/评估往往比训练贵，容易被漏算。

---

## 7. 选 checkpoint 的口径

**选择口径必须等于评测口径。** 用别人的默认监控指标选权重，等于优化另一个目标。

本仓库的两个实例：

- 训练框架默认按 `val/binary_auprc` 选，而目标是六项指标的均值 → 必须改监控键。
- 某监控项在训练中会**冻结**，导致 best checkpoint 永久停在第一个极小点，看起来像「训练没有进展」。判断「跑到第几步」只认 checkpoint 里的 `global_step`，不要用进度条。
