# 排障

每一节：症状 → **最便宜的检查** → 常见原因 → 修法。原则是先用一小时买到判断，再决定要不要花一天。

---

## 1. loss 是 NaN / inf

**先查顺序**（从便宜到贵）：

1. 输入里有没有 NaN/inf —— 一个 `torch.isnan(x).any()` 或 `np.isfinite(x).all()` 在 dataloader 第一层。
2. 学习率是否过大 —— 单独把 lr 降 10× 跑 50 步。
3. 梯度累积的除法有没有漏 —— 漏了 `loss/accum` 等于 lr 放大 `accum` 倍。
4. 损失里有没有 `log(0)` / 除零 —— 加 eps，或在分母上加掩码外的 1。
5. 损失里有没有在**全被掩码的行**上求均值 —— `sum / count` 里 `count = 0` 直接产生 NaN。这是掩码型任务最常见的 NaN 来源，且只在某些 batch 上触发，所以表现为「跑了几百步突然 NaN」。

**不要**先怀疑模型结构。NaN 在第几步出现能定位一半问题：第 1 步是数据，几十步后是 lr 或数值，几百步后是某个被掩码的 batch。

---

## 2. loss 卡在初值附近不动

**最便宜的检查**：打印**每个参数组的梯度范数**，看哪些是精确的 0。

- 某个新加的分支梯度为 0 → 计算图没接通。典型：零初始化输出层之后又接了一次 `detach`，或者该模块的输出从未被使用。
- 所有梯度都正常但 loss 不动 → 学习率太小，或调度器没生效。打印实际使用的 lr，别信配置。

**零初始化残差分支的专项检查**（这是本仓库反复踩的一类）：

零初始化让分支在 step 0 输出恒等于 0，这是设计意图；风险在于**它可能永远停在 0**。必须单独验证一次：

1. 前向：改动输入，分支输出应仍为 0（恒等性）。
2. 反向：分支最后一层的 `weight.grad` 必须非零。
3. 路径：改动输入张量的一个位置，检查输出中**其他位置**是否移动（证明信息确实流过去了）。

三项缺任何一项，你都会得到一个「训练正常、指标合理、但分支根本没启用」的实验。这类实验不会报错，只会让结论错。

---

## 3. 中途 loss 尖峰

**最便宜的检查**：把尖峰**前 20 步**的梯度范数打出来。梯度范数先于 loss 尖峰出现，所以尖峰本身定位不了原因，前缀可以。

- 单步梯度范数跳 10× 以上 → 要么裁梯度的阈值定得太松，要么某个 batch 的样本极端。
- 只在一个固定 step 跳 → 检查数据顺序，是不是某个稀有类别/背景在全 batch 里占比极高。

**滚动窗口**比固定阈值有用：记录每层 `abs().max()` 的滑动最大/最小，尖峰时回看是哪一层先炸。在深度网络里，先炸的层几乎总是问题所在层。

---

## 4. 平台期

按顺序排除，**不要**先加参数：

1. **学习率**：试 2–5× 更大。这是最常见的正确解。
2. **warmup 太长**：初期的学习率被压住，看起来像平台期。
3. **权重衰减太强**：把 wd 降到 0 跑一次。
4. **数据泄漏的反面 —— 切分太容易**：验证集和训练集同分布同背景，早就饱和了。
5. **容量**：最后才考虑。

如果训练 loss 在降而验证不动，先怀疑泄漏/分布差异，不是过拟合。

---

## 5. 静默泄漏

最危险的一类，因为 loss 曲线完全正常。

| 泄漏 | 检查 |
|---|---|
| 行级随机切分 | 切分单元是背景/供体/化合物时，随机切行会把同一单元的行分到两边。按单元切。 |
| 预处理在切分之前 | 标准化、分位数、目标编码必须在训练集上 fit。 |
| 输入由目标计算 | 逐个检查输入特征：有没有任何一列是从同一行的目标、或从包含该行的聚合统计来的。 |
| 检索式输入 | 如果输入是「相似样本的统计」，断言检索库与验证集行无交集。 |
| 外部知识源 | 预训练嵌入、先验表里可能含目标信息。**别人写的泄漏检查通常只覆盖它自己想得到的路径**，不覆盖你新接的知识源。 |

**检验手段**：把目标随机打乱后重训。如果验证指标仍然显著高于基线，说明有侧路把答案送进来了。

### 5.1 NaN 染色：往「不该来」的地方注入

比逐个审计泄漏点更有效：**在信息不该出现的位置注入 `NaN`，跑真实管线，看它扩散到哪。**

NaN 在 `+ - * /` 下是吸收元，像染料一样沿计算图扩散。如果任何「过去」或「训练集」的输出变成 NaN，就说明信息从那条不该有的路径流过来了；然后在管线中间插 `assert isfinite`，二分定位它从哪一步越过边界。

注入位置取决于你怀疑的侧路：测试集、未来时刻、标签、留出背景的响应行。

**两个必读的 caveat**（不写这两条，这个方法会给出假安全感）：

- **假阴性**：`pandas` 的 `mean/std/sum` 默认 `skipna=True`，`np.nanmean`、`dropna`、`fillna`、插补器、`rolling().mean()` 都会静默吞掉染料。**兜底：改用巨大哨兵值（如 `1e12`）**，它不会被 `nanmean` 吞掉，会在任何被污染的量上显示为荒谬值。
- **假阳性**：含 NaN 的轴上做 softmax 会全变 NaN（`NaN + (-inf) = NaN`），即使因果掩码是正确的。所以它**不能**用来验证 transformer 内部的因果掩码，那里改用下面的梯度检查。但「NaN 通过 batch 统计越过边界」通常是**真阳性**：一个在 train+test 上 fit 的标准化器，就是让 test 行污染 train 特征的那条路。

### 5.2 反传依赖检查（模型内部的泄漏/混样）

NaN 染色在模型内部会假阳性的地方，用它的梯度对偶：

1. 把 loss 换成**第 i 个样本输出的和**；
2. 反传；
3. 断言**只有第 i 个输入**的梯度非零。

这能抓 `view` / `transpose` 用错造成的跨 batch 维度混样——这类 bug 不会让 loss 变难看，只会让模型看到不属于它的样本。它也是验证「新增分支的输入真的影响输出」的标准做法，比手工看某几个张量可靠。

## 6. 「指标变好了」，但不确定是什么变好

**复合分数会伪装。** 先把指标拆成分量向量再看。

本仓库的实例：某次改动让六项等权均值从 +0.145 涨到 +0.245（+0.100），看起来全面进步；分解后 **+0.0945 来自单项 MSE**，其余五项合计只 +0.0055。也就是说这次改动的全部内容是「让一项变好」，另外四项基本没动——如果那四项才是你的对外主张，这个「进步」不成立。

规则：

- 每次比较都报分量向量。
- 均值的提升若集中在单一分量，明确写出「这是 X 项的改善」。
- 分量的量纲不同（有的有下界、有的对称），不要直接平均后再解释。

---

## 7. 差值是否可信

**配对比较**：两个臂必须在同样的样本、同样的留出集、同样的评测脚本上比。只比两个标量不算证据。

**噪声先标定，再解释差值。** 顺序颠倒就会把噪声当信号。

- 分半法：把评测集随机分两半各评一次，`SE ≈ |d1−d2| / 2.26`。这是最便宜的误差棒来源。
- 多种子：把种子当随机因子，报均值 ± SD。单种子峰值不能当预期值。
- **差值小于噪声就写「不可区分」**，不要写「略优」。

本仓库的实例：单臂峰值 +0.114，三种子 μ = +0.084 / SD ≈ 0.026。正确表述是「+0.08 ± 0.03」，不是「+0.114」。

---

## 8. 零对照是恒等式

做了零对照不等于对照有效。**先确认零对照的数值与真实对照不同**；相同说明你构造的扰动对统计量没有影响。

已知会犯的错：用**行置换**给一个只依赖**列**结构的统计量做零对照。对矩阵 `X` 做行置换 `P·X = (P·U)ΣVᵀ`，右奇异向量 `V` 完全不变——这个零对照在数学上等于真实对照。

有效的零对照必须打掉你声称的**对应关系**：

- 声称「基因级结构」→ 打乱基因轴（列），保持谱形。
- 声称「配对关系」→ 打乱配对，保持边际分布。
- 兜底：随机子空间（与数据无关的 k 维基），给出绝对下限。

三个都要报，因为只有一个时你无法区分「真实结构」和「任何 k 维子空间都有的谱巧合」。

## 9. 结果不能复现

先区分三种：

| 现象 | 含义 | 动作 |
|---|---|---|
| 指标逐位一致，但文件不同 | 抽样路径稳定、序列化不稳定 | 比较伪bulk 或聚合量，不比较单细胞级张量 |
| 指标差一点点（1e-6 级） | 浮点非确定性（kernel 选择、并行规约） | 可接受，但报告时给定容差 |
| 指标差很多 | 有未播种的随机源，或数据顺序变了 | 找随机源：采样、dropout、增强、worker 数 |

**同 seed 连跑两次要求逐位一致**，这是 G0 的一部分。做不到，说明你的实验对比从根上不可信——因为你永远无法确定两个臂的差异是改动带来的还是采样带来的。

推论：当上游某一步的抽样不可复现时（例如某次提交件的单细胞级抽样），**不要整份重跑**，只把改动的部分嫁接进去；重跑会把未改动的部分也重新掷骰。

---

## 10. 复现优先于诊断

**先复现，再诊断。** 同一个 seed 跑一次，再换一个 seed 跑一次。

- 同 seed 复现不了 → 这是「不可复现」问题，不是「性能」问题。写下来，单独查。
- 同 seed 能复现、换 seed 就变 → 这是种子敏感性问题（方差大），也不是性能问题。先估方差，再判断任何差值。
- 两个都复现 → 才可以开始找原因。

在复现之前提出的诊断，全都建立在一次不确定的观测上。

---

## 11. 同一个数字的第二个原因

诊断如果依赖某一个数，先问：**还有什么会造成同一个数？**

做法：把计算这个数的代码引出来（不是描述，是那一行），列出至少一个能产生同样数值的替代解释，再指出**哪个第二个指标能区分两者**。

已知的典型：

- 余弦接近 1 可以是「共享均值」也可以是「表示塌缩」——两者都不需要模型学到任何东西。
- 两个探针方向的余弦为 0 只说明它们正交，**不说明任一探针有效**，所以它什么都排除不了。
- 指标变好可以来自「模型更强」，也可以来自「评测更容易」——后者用留出面或换评测集区分。

---

## 12. 「A 优于 B」的三关

在说 A 优于 B 之前，四样东西必须是数字且带行号引用：**基线、机会水平、对照组、单个条件的种子分布**。

然后过三关：

1. **打乱对照**：把关键输入/标签打乱走同一管线，A 的优势是否消失？
2. **换评测面**：优势在「没被调过的」留出面/换写法的提示/另一个规模上是否还在？
3. **独立盲读**：把产物（不含结论）交给一个没有立场的读者，看他列出什么。把它列出的东西原样引用，包括「没发现问题」。

对**负结果**同样适用。负结果需要一个明确的范围，以及对合理替代解释的证据；「我试了 X，不行」的正确读法是「我试了 X 的**一种**实现（占 X 全部实现的极小一部分），它不行」。

---

## 13. 结构上限：它能不能表达

指标卡住，可能是优化器的问题，也可能是**参数化本身表达不了目标**。

最便宜的判别：**把这一项损失整个关掉，看指标是否到达同样的值。** 如果一样，说明这一项从来没有推动过它——不是学不动，是没连上或者不可表达。

配套的 oracle 替换：把管线里的每个组件依次换成「完美版本」（真实标签、oracle 输出），**哪个组件换掉后指标跳得最多，瓶颈就在哪**。如果换上完美标签指标几乎不动，问题不在模型，在它的上游（数据）或下游（度量）。

---

## 14. 反模式

完整清单在 `SKILL.md` 的「反模式」一节——那里是每次调用都会读到的位置，重复写会漂移。

排障时额外记两条数值细节：

- **裁剪会掩盖问题**：记录裁剪**前**的范数，看它是否每步都在触发。裁剪阈值是任务属性，不是通用常数。
- **AdamW 下 `lr × grad` 不是实际更新量**：要看 `optimizer.step()` 前后的参数变化幅度。

---

## 15. 两次诊断周期没有进展：去读可用的实现

如果一两轮诊断都没有定位问题，停止猜测，去找一个能跑的参考实现。**这一步通常比再猜一轮更值。**

读三样东西，逐项写下来：

| 项 | 看什么 |
|---|---|
| 算法本身 | 与你的计算图逐项对照。bug 通常是「小事」：符号、重置、off-by-one、漏掉的归一化。 |
| 论文没写的工程技巧 | 输入标准化了吗？激活函数？池化方式？层数？梯度饱和时的裁剪？热启动？数据集是不是比你的简单？ |
| 已验证的超参 | 先照抄能跑的值，再调自己的。 |

参考实现的挑选按可信度排：有结果表 > 有别人复现的 issue > 多人贡献 > README 写了评测细节 > 别人 import 它。

对照表写法：

| 特性 | 对方（文件:行） | 我 | 一样吗 |
|---|---|---|---|

如果逐项都一样，再做二分：整段照搬对方的代码，确认能跑，然后一半一半地换回自己的。
