# 排障

每一节从症状出发，先做最便宜、能区分替代解释的检查。任务契约、泛化轴与四道检查以 `SKILL.md` 为准；实验归因和运行产物以 `run-artifacts.md` 为准。本文件提供诊断方法，不把一次观测直接升级为因果结论。

## 1. loss 是 NaN / inf

先保存首个异常 batch 的 ID、掩码、配置与随机状态，再沿真实路径定位**第一个非有限量**：

1. 检查输入、目标、变换结果、模型输出和各项 loss 的 `isfinite`，不要只看最终总 loss。
2. 检查 `log(0)`、除零、溢出及非法概率。是否加 eps、跳过还是拒绝该样本，取决于数学定义；不能用 eps 掩盖错误掩码或不合法数据。应在非法运算前选择有效项，不能指望事后乘零或过滤结果就保证反向安全，见 [PyTorch：除零与 Autograd](https://docs.pytorch.org/docs/stable/notes/autograd.html#division-by-zero-in-autograd)。
3. 检查全掩码行与有效权重总和为零的窗口。无有效监督的窗口应有显式策略，不能计算 `sum / 0`，也不能假装完成有效更新。
4. 核对梯度累积的归一化，尤其是不同 microbatch 的有效基因数、权重和末尾不足窗口，见 `recipes.md` §2。
5. 输入与目标有限后，再用小切片比较 FP32 与当前 AMP 路径，检查 loss scale、实际学习率、梯度与参数更新；需要时做有界的学习率对比。

异常出现的步数只是线索。第 1 步也可能是数值实现错误，后续异常也可能来自坏数据、稀有 batch、优化不稳定或溢出；不能按“第几步”确定病因。

## 2. loss 卡在初值附近不动

先核对可训练参数是否进入 optimizer、`requires_grad`、训练/评测模式、实际学习率、梯度与 step 前后的参数差异。冻结参数没有梯度是预期行为。

- `grad is None` 与梯度张量恰为 0 要分开记录；两者都需要结合清零方式、参数是否参与本轮计算来解释。
- 零梯度可能来自 `detach`、输出未使用，也可能来自零初始化、ReLU 未激活、饱和、局部极值、损失掩码、不同项抵消或离散操作。一个 batch 的零梯度不能证明结构断路。
- 梯度非零但参数不动时，检查 optimizer 参数组、学习率、AMP 跳步、冻结逻辑和更新精度；参数在动但 loss 不动时，再查尺度、指标分辨率、优化与容量。
- 输入依赖检查不要只对输出求和：分量之间可能抵消。选择多个输出分量或随机投影，并结合多个输入点的有限扰动，见 §5.2 与 `htca-bboc.md`。

**零初始化残差分支要分阶段验证：**

1. 初始化时，按设计检查残差为零、与原模型输出在约定容差内一致。此时“改输入仍不改变残差”可以是预期现象。
2. 在有监督、非退化的小 batch 上检查末层梯度和实际更新。上游层初始零梯度可能来自零末层；若未更新，检查替代原因，不能立即判定路径断开。
3. 完成少量有效更新、确认分支已离开零后，再改动输入，检查设计要求的输出分量是否响应。只有设计包含跨基因作用时，才要求其他基因输出变化。

分别记录恒等性、激活过程和激活后的依赖；不能在同一初始化状态同时要求“输出恒零”和“输入扰动能改变输出”。

## 3. 中途 loss 尖峰

先对齐异常前后的 batch、各项 loss、有效监督数、实际 lr、裁剪前梯度、AMP scale/跳步和参数更新。梯度可能提供预警，但不保证先于 loss 尖峰。

- 重放固定 batch，区分数据相关异常与更新历史相关异常。
- 检查稀有背景、极端目标、有效掩码骤减、损失权重及归一化变化。
- 用层级统计或短窗口 hook 定位最早出现异常的张量；最先观测到异常的层不一定是根因。
- 梯度范数只有在相同归一化、相同缩放口径下才可比较。AMP 下在累积完成并 unscale 后测真实范数，顺序见 `recipes.md` §2。

## 4. 平台期

在契约和正确性检查之后，用小预算区分：

1. 实际学习率或调度是否与配置一致；在稳定范围内对比更大/更小 lr，不能默认“增大 2–5 倍必有效”。
2. 正则、梯度裁剪、AMP 跳步是否压制更新。
3. 训练目标是否改善，而验证指标因尺度、渲染、阈值或分辨率而不动。
4. 训练与验证的差距是否符合过拟合、分布偏移、覆盖不足、噪声上限或评测饱和。
5. 冻结表征、适配器秩与容量是否足以表达当前目标。

训练 loss 降而验证不动**可以是过拟合**，也可能有其他原因。先提出可区分解释的小实验，证据不足时写“不确定”。

## 5. 静默泄漏

loss 曲线正常不能排除泄漏。先按任务契约标出训练、验证、最终测试及部署时允许的信息，再审计实际依赖：

| 路径 | 检查 |
|---|---|
| 错误切分 | 按需要泛化的 donor、背景、扰动及其组合检查交集；已知扰动跨背景出现可能是任务设计，不能一概判泄漏 |
| 预处理 | 需学习总体统计的标准化、插补、特征选择、目标编码只在允许分区 fit；单样本自身的确定性变换单独说明 |
| 目标派生输入 | 检查是否使用了当前样本或留出组的响应；训练分区合法构建的先验及部署可获得的 control 不能自动视为泄漏 |
| 检索与缓存 | 审计来源、实体别名、fold、生成配置和内容；不能只断言原始行号无交集 |
| 外部知识源 | 记录版本、训练覆盖与潜在目标信息；未知预训练覆盖应写成主张限制，不能宣称已证明无泄漏 |
| 模型选择 | checkpoint、超参、阈值与校准仅使用契约规定的开发分区；最终测试响应不得参与任何选择 |

打乱标签后重训是辅助检查，必须明确打乱什么对应关系、保留什么分层，并在独立留出单元上与相应零基线比较。训练集能够记住随机标签是容量现象；留出指标仍高时，应查残留相关性、边际分布、指标定义与侧路，不能凭一次打乱就确定泄漏或证明安全。

### 5.1 NaN 染色与有限哨兵

在**数据副本与隔离缓存**上，将不允许使用的信息替换为 NaN、适当量级的有限哨兵或不同的有效取值，跑真实管线并比较中间产物。不得污染原始数据、正式缓存或最终测试产物。

- NaN 可沿部分算术传播，但 `nanmean`、`skipna`、`fillna`、过滤等会吞掉它；有限哨兵也可能被 clip、归一化、分箱或缓存遮蔽。
- 巨大值可能溢出、触发不同分支或破坏整个 batch；它不是无条件更强的兜底。先验证哨兵能穿过待测变换，并设置阳性对照。
- softmax、掩码乘法与 batch 统计可能扩散 NaN，即使有限数值下设计的依赖约束正确。发现污染后，需用有效取值干预及来源追踪确认是否违反信息契约。
- 未见扩散只能写“在所测输入和路径中未发现影响”，不能写“证明没有路径”。缓存键、静态代码审计与多种干预仍需互相补充。

### 5.2 模型内部的依赖与混样

先写出允许的依赖：独立逐样本模型、训练态 BatchNorm、集合模型、跨样本 attention 的预期不同。合法的跨样本交互也仍须满足部署信息边界。

1. 选择第 i 个样本的多个输出分量或随机投影，记录其对各输入的梯度；冻结其他随机性。
2. 用有限扰动、替换或删除输入补充检查，比较 train/eval 模式及改变 batch 同伴后的结果。
3. 若设计要求逐样本独立，出现非预期跨样本影响时，查 `view` / `transpose`、归约维度与 batch 统计；若设计允许交互，则查交互对象是否包含禁止的信息。

梯度为零只是局部观测；离散路由、零初始化、非光滑或抵消都可能使检查不敏感。不要把单个输出和的零梯度当作结构证明。

## 6. 「指标变好了」，但不确定是什么变好

报告预先约定的主指标及其分量，检查改善是否集中于少数背景、扰动、基因或评分项。不同量纲的指标只有在定义明确的归一化和固定权重下才能组成可解释的复合分数；仍需提供分量。

维护者在脱敏案例中描述过“总分主要由单项带动”的现象，详见 `case-study-perturbation.md`。这是解释指标的示例，不是当前任务已经发生的测量结果。贡献与因果归因规则以 `run-artifacts.md` 为准。

## 7. 差值是否可信

两个臂在相同留出单元与同一评测实现上做配对比较。先明确估计对象和独立单位，不能把同一 donor 的多个细胞或同一样本的多个基因当成独立重复。

- 可在独立 donor、背景或实验重复层面做**配对 cluster bootstrap**：每次对同一批组重采样，同时重算 A、B 及差值；保留组内相关性和原指标权重。
- donor、背景与扰动若是嵌套或交叉结构，应采用匹配设计的分层/多向方法，或分别报告清晰的泛化面，不能任选一层后忽略另一层相关性。
- 报告重采样单位、独立组数、方法、区间及适用假设。独立组很少时，给组级差值和限制；不要制造精确误差棒。
- 多种子描述优化与采样随机性；跨 donor/背景的变异描述生物样本或泛化不确定性。**两者不是同一种方差**，应分别报告，不能互相替代。
- 区间包含零或证据不足时写“当前证据不能区分”；不能据此证明等效。声称等效需要预先定义实际差异容限及相应分析。

不使用单次随机分半差值除以固定常数来估计通用 SE；单种子峰值也不能代表预期性能。

## 8. 零对照是否打掉了目标关系

先说明零假设和需要打掉的对应关系，再检查变换对统计量是否可能恒等。真实对照与零对照数值相同不自动表示对照无效，也可能符合零假设、显示效应很小或度量不敏感。

典型数学陷阱：行置换 P 满足 `(PX)ᵀ(PX) = XᵀX`，因此右奇异子空间不变；重复奇异值下具体基的方向还可能不唯一。用这种变换检验列结构，通常打不掉所声称的结构。

可选对照依主张选择：

- 基因对应关系：只打乱待检验的基因映射，保持外部标签坐标固定；若所有相关轴同时置换，可能仍是恒等变换。
- 样本/模态配对：在可交换的分层内打乱配对，保留需要控制的边际分布。
- 子空间结构：与匹配秩、尺度及必要谱性质的随机结构比较；随机子空间是参照分布，不是必然的性能下限。

校验阳性/阴性对照并重复采样；不要求每种任务都机械报告同样三种对照。

## 9. 结果不能复现

采用任务契约约定的三层判据：

| 层 | 检查 | 解释 |
|---|---|---|
| 数据与配置 | 输入/切分/缓存哈希、处理版本、随机状态、样本顺序 | 先排除比较对象改变；相同 seed 不会自动控制所有来源 |
| 固定环境数值复现 | 相同软件、硬件、精度与确定性设置下，按预设 atol/rtol 比较关键张量与指标 | 可实现时使用逐位一致；微小差异本身不等于管线失效，容差不能事后为结果量身设置 |
| 统计复现 | 不同种子与独立生物单元的差值、方向和不确定性 | 检查主张是否对合理变动稳健，不要求不同种子相同数值 |

指标相同不能证明所有单细胞张量、抽样路径或文件内容相同；文件不同也可能只是序列化元数据不同。分别比较所需层级的内容。

按实际版本控制 Python、NumPy（含独立 Generator）、PyTorch、DataLoader worker 与采样器，记录确定性算法设置。跨版本、平台或 CPU/GPU 不保证完全复现，参见 [PyTorch Reproducibility](https://docs.pytorch.org/docs/stable/notes/randomness.html)。

若上游抽样不稳定，可先固定输入快照和随机流做配对诊断；这只能支持该条件下的比较。最终端到端验证仍需覆盖上游变化，不能把拼接产物当作完整复现。

## 10. 复现与诊断相互补充

先保存可重放的最小失败样本，优先检查低成本、确定性的事实；无需等昂贵的多种子重训完成，才检查明显的形状、掩码或非有限值错误。

- 同 seed 差异超过约定容差：查环境、随机性及实现，并限制差值解释。
- 换 seed 结果改变：量化随机性；差异不一定表示“方差大”，也不自动否定性能。
- 多次运行一致：只说明所测范围内稳定，不保证实现或解释正确。

复现失败、性能不足和科学主张不成立可能同时存在，应分别记录。

## 11. 同一个数字的第二个原因

诊断依赖某个数时，引用其计算位置，列出至少一个替代解释，再指出能区分两者的第二个检查。

- 余弦接近 1 可能来自真实结构、共享均值或表示塌缩。
- 两个探针正交只说明几何关系，不证明任一探针有效。
- 指标变好可能来自模型改善，也可能来自更容易的评测、不同覆盖或选择偏差。

证据不足时保留多个解释，不能为了填报告而指定一个机制。

## 12. 「A 优于 B」的证据检查

结果的比较设计与归因遵循 `run-artifacts.md`。诊断时核对：

1. 基线、对照、指标和适用的机会水平是否明确；回归任务不一定存在一个通用机会水平。
2. 关键对应关系的打乱/消融是否支持声称的机制，且对照本身有效。
3. 优势是否来自未参与调参的留出单元；只要测试结果指导了选择或修改，就不能继续称其为独立确认。
4. 有条件时由独立审阅者检查产物；“未发现问题”是审阅结果，不是正确性证明。

对负结果也限定数据、实现、预算和不确定性；一次实现失败不能排除整个方法族。多个改动同时发生时，只能先归因于整体方案，分项贡献需因子实验或适当消融。

## 13. 结构上限：它能不能表达

单批拟合失败先检查目标是否可达：重复输入是否对应冲突标签、损失是否有非零下界、冻结表征是否丢失必要信息、适配器容量是否受限，再区分优化与实现问题。

关闭某项 loss 后指标相同，只说明该比较未观测到其作用；可能是冗余目标、权重过小、噪声、优化不足、指标不敏感或结构约束。结合该项梯度、实际更新、容量对照与合成可解任务，不能据此断言“没连上或不可表达”。

oracle 替换用于定位候选瓶颈：在隔离诊断中替换一个组件，检查下游对理想输入的响应。oracle 可能改变输入分布或接口，也可能受其他组件联合限制；最大改善不等于唯一根因。使用真实标签的 oracle 产物不能计入可部署性能。

## 14. 数值诊断边界

- 裁剪前的范数能显示裁剪频率；阈值要结合损失归一化、可训练参数、优化器与实际任务验证。裁剪是稳定手段，也可能遮蔽上游异常。
- AdamW 的实际更新含状态、预条件与权重衰减；`lr × grad` 不是实际更新量。必要时测 step 前后的参数差异。
- AMP 下检查/裁剪顺序与累积规则见 `recipes.md` §2；不要为读梯度而在每个 micro-step 提前 unscale。

## 15. 诊断没有进展：对照可用实现

一两轮检查仍不能区分主要解释时，寻找任务、数据表示和版本相近的参考实现，核对算法、处理、形状、归一化、优化及评测。仓库受欢迎、有人 import 或有结果表，都不能单独证明实现可靠。

| 特性 | 参考实现（commit / 文件:行） | 当前实现 | 差异与待验证假设 |
|---|---|---|---|

在隔离分支中复现最小参考流程，再逐段替换定位；先检查许可证、接口与数据契约。不能照搬一次成功配置后宣称已经找出因果原因。
